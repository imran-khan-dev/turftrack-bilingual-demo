## Ambiguous translation choices

Eight terminology choices merit product-owner or native-speaker review during implementation: “slot” (kept as “slot”/“সময়স্লট” depending on context), “field” (sports field vs form field), “venue” (kept as Venue), “settlement” (financial নিষ্পত্তি vs weekly পরিশোধ), “due” (amount due vs due date), “charge” (fee vs transaction charge), “refund” (kept as Refund), and “manager action” (wording depends on the action value). Suggestions are natural Bangladeshi Bangla drafts, not a final product glossary.

## Static scan limits

- This is a source-level inventory. Runtime copy arriving from API/server error payloads was not inventoried because API/database values were expressly out of scope; those messages need their own contract/source review.
- Static extraction can miss copy assembled from nested JSX fragments, conditional fragments, generated validation rules, or values assembled in helpers. Dynamic messages found during review are recorded with `{variable}` placeholders, but a runtime UI pass is still needed before calling extraction complete.
- Only source strings that appear user-facing are included. IDs, routes, URLs, enum values, code identifiers, comments, and debug output are excluded. Enum/status entries in the inventory are suggested display labels, not translations of stored values.
- Public addresses, email addresses, and illustrative input values (for example “Dhaka Strikers” and “Gulshan, Dhaka”) are preserved verbatim and called out in their row context.
